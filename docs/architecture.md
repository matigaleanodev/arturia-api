# Architecture

[Español](architecture.es.md)

Arturia API serves conversations organized by user and scope. A turn is accepted over HTTP, persisted together with an outbox intent, relayed to an SQS FIFO queue and generated by a worker that writes text blocks; the client reads them over SSE.

## Interface

- [`contracts/openapi.json`](../contracts/openapi.json) and [`contracts/sse.schema.json`](../contracts/sse.schema.json) define the HTTP and SSE interface, including the public error shape. Fixtures live in [`contracts/fixtures/`](../contracts/fixtures/).
- [`src/http/routes.ts`](../src/http/routes.ts) lists every route once; the Lambda adapter and the API Gateway composition share it.
- Conversation titles and message text accept up to 393,216 UTF-8 bytes each. Scope, conversation and turn IDs in paths accept up to 256 UTF-8 bytes each. Oversized values return HTTP 400 with code `INVALID_REQUEST`.
- The turn events endpoint accepts an optional nonnegative integer `after` cursor. It reads persisted blocks, rechecks the current session and scope grant before each batch, and closes after the terminal status, revocation, or the connection time limit. Clients reconnect with the last text sequence received. Heartbeat comments carry no data.

## Lambda handlers

`npm run bundle` builds one self-contained Node.js 24 bundle per handler in `dist/bundles/<name>/index.cjs`. `BUNDLES` in [`infra/delivery.ts`](../infra/delivery.ts) lists the entry points, which must live in `src/`.

| Bundle | Handler | Configuration |
|---|---|---|
| `http` | REST proxy for conversations and turns (`src/http/turns.lambda.ts`). | `ARTURIA_TABLE_NAME`, `ARTURIA_CLIENT_ID`, `ARTURIA_ALLOWED_ORIGIN` |
| `worker` | SQS consumer of turns (`src/chat/generate.lambda.ts`). `retry`, invalid messages and failures become `batchItemFailures`; in a FIFO batch the remaining messages are returned unprocessed. | `ARTURIA_TABLE_NAME`, `ARTURIA_ENVIRONMENT`, `ARTURIA_PROVIDER_MODE` |
| `stream` | SSE turn events in streaming mode (`src/chat/stream.lambda.ts`). | `ARTURIA_TABLE_NAME`, `ARTURIA_CLIENT_ID`, `ARTURIA_ALLOWED_ORIGIN` |
| `relay` | DynamoDB stream outbox relay to SQS (`src/jobs/outbox.worker.ts`). | `ARTURIA_TABLE_NAME`, `ARTURIA_TURN_QUEUE_URL` |

The `http` and `worker` handlers read and validate their configuration once per execution environment. An invalid configuration fails closed: HTTP answers `500 INTERNAL_ERROR` with the public error shape, and the worker fails the invocation so every message returns to the queue.

## API

`addChatApi` in [`infra/chat-api.ts`](../infra/chat-api.ts) creates the Regional REST API and its Cognito authorizer. It calls `addChatStream` in [`infra/chat-stream.ts`](../infra/chat-stream.ts) to register the GET events route and its delivery Lambda. Delivery requires an existing Arturia session.

The SSE route invokes the `stream` function with response streaming and a 29 s integration timeout, below the 15-minute streaming limit of REST APIs. Instead of long-lived connections, clients reconnect with the `after` cursor, so a closed connection never loses blocks.

## Turn processing

Durations live in [`src/config/timing.ts`](../src/config/timing.ts), shared by the code and the CDK composition and validated at synthesis:

- Provider timeout (45 s) plus a closing margin is below the worker timeout (60 s), which the turn lease (75 s) covers.
- `TurnQueue` visibility (360 s, six times the function timeout) exceeds worker timeout plus lease, so a redelivery always finds an expired lease.
- Three worst-case persistence operations fit the closing margin, and the transport timeout is below the provider deadline.

The event source delivers one message per invocation with partial batch responses and a maximum concurrency of 2, instead of reserved concurrency. Messages are retained for 14 days and move to the FIFO dead-letter queue after 5 receives.

The message group is a hash of user and scope: a retried turn holds back later turns of the same user and scope for the whole visibility, never those of another scope or user. A redelivered turn whose send crossed the provider boundary ends as `SEND_UNCERTAIN` and is never sent or reserved again.

The worker clamps the provider deadline to the time left in the invocation minus the closing margin, and retries before claiming a turn when that window is too short. The DynamoDB client of every function has bounded connect and request timeouts (the request timeout is only enforced with `throwOnRequestTimeout`) and two attempts per operation; transactions reuse their client request token across attempts. If DynamoDB stays degraded past the margin, Lambda ends the invocation and the turn stays uncertain until its lease expires, which never produces a second provider call.

## Model dispatch

Billable workers use `dispatchModel`. Chat uses `createTurnDispatcher` to read the current account, session, scope, turn lease, message and source grants in one DynamoDB snapshot before any send. Egress rules are described in [Security](security.md#model-egress) and spending rules in [Cost controls](cost-controls.md).
